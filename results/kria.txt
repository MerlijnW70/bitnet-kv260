  Three source patches were required on this fork for ARM (files patch-quants.diff, patch-i2s.diff, patch-bitnet.diff
  next to this file; applied with the unpatched originals kept as *.orig, then the same cmake --build):
   1. ggml/src/ggml-cpu/quants.c  ggml_vec_dot_i2_i8_s_1x1: only an AVX2 kernel exists; the non-AVX2 scalar fallback
      used the wrong bit layout (4 consecutive weights per byte; the GGUF packs 128-weight blocks of 32 bytes,
      byte k = weights k, 32+k, 64+k, 96+k, per utils/convert-hf-to-gguf-bitnet.py and the AVX2 code) and mapped
      codes to -1/0/+1 although the caller subtracts the activation sum again. Added a NEON kernel (vmull/vmlal_s8 +
      vpadalq_s16, vdotq_s32 when DOTPROD is present) with the right layout and raw-code convention; scalar fallback
      fixed the same way. Unit test ktest.c vs a scalar reference: 0 mismatches in 800 rows of n=2560.
   2. ggml/src/ggml-cpu/ggml-cpu-i2s.c  ggml_gemm_i2_i8_s non-AVX2 fallback (ACT_PARALLEL) called vec_dot with
      nrc = activation columns and a strided output, but the kernel treats nrc as weight rows with contiguous output;
      every prompt batch (>= 4 tokens) was garbage. Replaced by one vec_dot call per activation column.
   3. src/models/bitnet.cpp  the bitnet-b1.58 graph built the FFN with LLM_FFN_SILU; BitNet-b1.58-2B-4T uses squared
      ReLU -> LLM_FFN_RELU_SQR for LLM_ARCH_BITNET_B158.
  Two runtime flags were also required:

QUESTION (a)
  What is a CRC-32 checksum, and why does hardware compute it with a shift register? Answer in three sentences.
ANSWER (a), verbatim, stopped at <|eot_id|> after 69 tokens
  A CRC-32 checksum is a type of error-detecting code used to verify the integrity of data. It's computed by a hardware-based algorithm that uses a shift register to perform bitwise operations. This process involves dividing the data into blocks, computing a polynomial remainder for each block, and then combining these remainders to produce the final checksum.
